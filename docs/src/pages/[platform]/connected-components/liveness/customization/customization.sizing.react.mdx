## Sizing

`FaceLivenessDetector` always takes the full width of its container. Its height depends on the container:

- **Container without a set height** (for example, a normal page): the camera area's height follows the camera frame's 4:3 aspect ratio.
- **Container with a set height** (for example, a modal body with `height` or `flex: 1`): the component fills the container's full width and height. To fill the height, the camera view is scaled up and may be cropped on the left and right, by no more than 30% of the frame width, so the oval always stays fully visible. The top and bottom of the camera view are never cropped.

The camera area doesn't shrink below 200px tall. If the component is resized after the camera starts, for example by a modal open animation or a window resize, the camera view and oval resize with it.

Render size doesn't change how close the user needs to be to the camera. The oval and face-match thresholds come from the Face Liveness session and are evaluated in camera pixels.

```jsx
<div style={{ height: '80vh', display: 'flex', flexDirection: 'column' }}>
  <FaceLivenessDetector
    sessionId={createLivenessApiData.sessionId}
    region="us-east-1"
    onAnalysisComplete={handleAnalysisComplete}
    disableStartScreen={true}
  />
</div>
```

On mobile devices, the camera is shown full screen during the check, so the container's size doesn't apply there.

## Device orientation

The check runs in either orientation. A user can start it with the device held in portrait or in landscape, which matters for foldables whose cover screen defaults to landscape and cannot be rotated to portrait.

In a short landscape viewport the camera frame is letterboxed to fit the available height, and the hint and the match progress indicator move beside the oval rather than above and below it, since the oval spans nearly the full height there.

Rotating the device during a check does not fail it. The camera frame is fixed for the session, so only the rendered layout changes, and the component shows a prompt asking the user to hold the device still. The prompt clears as soon as the original orientation is returned to. It is not open-ended: a Face Liveness session expires three minutes after it is created and its session ID cannot be reused, so if the device is still turned away after 15 seconds the check times out with a retryable error rather than waiting for the session to expire.

Earlier versions failed the check with a `MOBILE_LANDSCAPE_ERROR` as soon as a mobile device was turned to landscape. That error is no longer emitted. See the [migration note](https://github.com/aws-amplify/amplify-ui/blob/main/packages/react-liveness/CHANGELOG.md) if your `onError` handler depends on receiving it.
